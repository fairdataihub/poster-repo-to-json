# Azure delivery layout

The normalized, license-enforced corpus is delivered to the Azure Blob container
`devboxposters/dev`. It ships as **two run folders at the container root**, each named
by the poster date-span of its run:

```
dev/
  poster_index_19860101-20241231/     <- "pre-2025" harvest run (24,165 posters)
    merged/
      zenodo/    <id>_complete.json
      figshare/  <id>_complete.json
    thumbnails/                        <- generated by the platform (not by this repo)
  poster_index_20250101-20251231/     <- "2025" harvest run (7,198 posters)
    merged/
      zenodo/ ...
      figshare/ ...
    thumbnails/
```

**Index both** for the complete corpus (24,165 + 7,198 = 31,363).

## What each folder contains

- `merged/{zenodo,figshare}/<id>_complete.json`, one poster.json per poster,
  schema-aligned (`poster_schema.json`) and normalized (publishers, funders,
  affiliations, subjects, conference locations, `researchField`/`domain`).
- Both runs are **full corpora with blocked posters kept as metadata-only**: a poster
  whose license does not permit redistributing derivatives (blocked, or unknown/unlisted
  -> default-deny) is present but stripped of poster-derived content
  (`content`/`imageCaptions`/`tableCaptions`/`researchField`/LLM descriptions) and carries
  `_license_blocked: true`, with no thumbnail. See [LICENSE_POLICY.md](LICENSE_POLICY.md).

## Notes on the folder names

The names are each run's poster date-span, following the platform's
`<label>_<YYYYMMDD>-<YYYYMMDD>` convention. They are **nominal**: the two runs are
separate harvest batches of *different* posters, not strict date partitions, their
publication dates overlap (the pre-2025 run reaches into 2025; the 2025 run contains some
older posters). Treat the folders as "run 1 / run 2", not as exclusive date buckets.

## Delivery mechanism

`scripts/post_processing/qc7deliver.sh` (on the processing host) `azcopy sync`s each local
merged corpus to its run folder with `--compare-hash=MD5`, so re-runs upload only changed
files. A clean re-run reporting 0 transfers means Azure matches the local corpus
byte-for-byte.

## Legacy / upstream prefixes (do not index)

The container also holds earlier or intermediate stages that are **not** the current
patched corpus: `dev/merged/`, `dev/posters/`, `dev/posters-2025/`, `dev/work-2025/`,
`dev/metadata/`, `dev/extractions/`. Index only the two `poster_index_*` run folders above.
